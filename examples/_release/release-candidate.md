## Failures and open items

1. **LangChain JS and `gpt-5.6` ids.** `Error: 404 No route for POST /v1/responses` (also `{"error":{"message":"No route for POST /v1/responses","type":"not_found_error","param":null,"code":"not_found"}}` from plugboard, an OpenAI-shaped body). Client quirk, same as the earlier record. Not a regression.
2. **`response_format: {"type":"json_object"}` content is not always bare JSON.** Same request on 2026-10-11 around 17:30, `Estimate: 2 boiled eggs and a slice of toast.` Haiku returned the JSON inside a fence: `'```json\n{\n  "food_item": "2 boiled eggs and a slice of toast",\n  "calories": 250,\n  "protein_g": 18, ... }\n```'`, `finish_reason` `stop`. `fast` and `gpt-5.6-luna#low` returned bare JSON. This is why `vercel_ai.ts compat` S6 reports `could not parse the response` on haiku. It looks like model behaviour behind the system-instruction mapping for `json_object`, not a routing fault, but a client that needs strictly valid JSON in this mode gets a fence on some models. The same fence shows in the LangChain JS `jsonMode` run. Not changed here.
3. **One `fast` flake, `S1`.** `fast` (`opencode-go/glm-5.3-flash`) answered `pin` (3 completion tokens, `finish: stop`) to "Reply with exactly: pong" in `bun vercel_ai.ts openai-chat` at 17:13:49; the session `ses_ed32f6c98ffepbBdulbJZeHGPd` holds exactly that assistant text, so the reply came from the model. Five reruns of the same request passed. Model behaviour.
4. **`fast` sends no response headers while it reasons.** `fast` on "Write the numbers 1 to 400 each on its own line, with a short sentence about each. No other text." produced only reasoning (22 to 40 KB) and no visible output; a client with a 60 s timeout got no status line at all and an `curl -m 90` timed out with 0 bytes received (`curl: (28) Operation timed out after 90001 milliseconds with 0 bytes received`). The same prompt on haiku had headers after 0.9 s. This follows from "the first visible output decides the status" and is not a leak (the sessions were interrupted when the clients left), but a client with a short header timeout will fail on reasoning-heavy requests even with `stream: true`. Not changed here.
5. Not covered: Open WebUI and n8n re-runs, `openai-default` mode, streaming `tools` plus `json_schema`, a long sequential (non-parallel) multi-tool turn, process memory under a stalled reader.
