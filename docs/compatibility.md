1. @anthropic-ai/sdk, structured: output_config.format (structured outputs) is refused with a 400; plugboard maps json_schema only on the OpenAI and Gemini endpoints
2. @google/genai, n: candidateCount above 1 is refused with a 400 (only one candidate is served); the OpenAI endpoints serve n
3. ai + @ai-sdk/google, model-id: the AI SDK sends an id with a slash without the models/ prefix (it treats a slash as a full resource name), so the request misses the Gemini route (404 naming the expected path, #150); the @google/genai rows pass
4. @langchain/anthropic, stream-usage: message_start reports input_tokens 0; the real input count arrives only in message_delta, so a client that reads usage from message_start sees 0
5. @langchain/google-genai, model-id: LangChain's Google class sends the model id without the models/ prefix, so the request misses the Gemini route (404 naming the expected path, #150); the @google/genai rows pass
6. @langchain/google-genai, cancel: the @google/generative-ai SDK that LangChain uses reports the client's abort as an unhandled 'Error reading from the stream'

Scenarios:

- **text**: One prompt, one text answer.
- **stream**: The same answer streamed, reassembled by the client.
- **tools**: A tool call, the client sends the result back, the model answers (full round trip).
- **parallel-tools**: Two tool calls in one turn, both answered.
- **image**: A PNG sent inline reaches the model as an image.
- **structured**: JSON Schema output parsed by the client.
- **error**: A provider 429 surfaces as the client's own error type with status 429.
- **usage**: Token usage is reported in the client's usage fields.
- **multi-turn**: A second turn: the client resends the conversation with the model's answer, and the model answers from it (#103, #104).
- **thinking**: Extended thinking on: the reasoning comes back as thinking content, then the answer (#102).
- **stop-sequence**: A stop sequence ends the answer, and the stop reason says so (#102).
- **n**: Several choices from one request (n > 1), each with its own index (#106).
- **stream-usage**: Usage arrives in the stream when the client asks for it (#106, #7).
- **developer**: A developer-role message (OpenAI's name for a system prompt) is accepted (#7).
- **echo-suffix**: Legacy completions options: echo the prompt and take a suffix (#106).
- **count-tokens**: Token counting before a request (count_tokens, countTokens) returns a count (#102, #103).
- **document**: A PDF sent as a document block reaches the model as a document (#102).
- **model-id**: A model id with a `/` (provider/model) is passed through to the route unchanged (#103).
- **prompt-array**: Legacy completions with an array prompt: one choice per prompt, each with its index (#106).
- **logprobs**: Logprobs absent: a client that does not ask gets null logprobs; one that asks is refused with a 400 (#105).
- **cancel**: The client aborts mid-stream and the server sees the abort on the model call (#101).

## Python clients

Run by hand with `bun run compat:python` (`compat/py/clients/`, a uv project pinned by `compat/py/uv.lock`). They are not in CI: the packages were not timed against the CI budget, and the run needs a Python environment CI does not set up. With no `PLUGBOARD_URL` the run starts the scripted fake (`test/support/fake-server.ts`); with `PLUGBOARD_URL` and `PLUGBOARD_KEY` set it runs against that server. Each client's record is in [`compat/results/`](https://github.com/jjjermiah/opencode-plugboard/tree/main/compat/results); the scenarios are the harnesses themselves.
